# 部署手册（Linux 测试机 / 生产机通用）

本文记录**实测可用**的部署流程与踩过的坑。路径按测试机 `/opt/artex` 写，
生产机同构，换路径即可。

## 0. 前置

- 二进制来自 GitHub Release（CI 构建，7 个 asset）：
  `artex-<版本>-linux-amd64.zip` + `SHA256SUMS`。
- **必须校验 SHA256**，官方 `SHA256SUMS` 里对应行必须 OK 才部署。
- 下载走 GitHub API 的 asset URL（`Accept: application/octet-stream`），
  或 `browser_download_url` 跟随 302。**asset 名字不带 `v` 前缀**：
  tag 是 `v0.3.66`，asset 是 `artex-0.3.66-linux-amd64.zip`。

```bash
sha256sum artex-0.3.66-linux-amd64.zip
grep 'linux-amd64' SHA256SUMS | sed 's/  */  /' | sha256sum -c -
# → artex-0.3.66-linux-amd64.zip: OK
```

## 1. 备份（不可跳过）

```bash
TS=$(date +%Y%m%d-%H%M%S)
BK=/root/artex-backup/pre-deploy-$TS
sudo -n mkdir -p "$BK"
sudo -n -u postgres pg_dump artex | gzip -1 > "$BK/artex.sql.gz"

# pigz 多线程；**-p 8 在 3.3G 的 sqlite 上会被 OOM 杀掉**，用 -p 2
sudo -n tar --use-compress-program="pigz -p 2 -1" -cf "$BK/data-traffic.tar.gz" -C /opt/artex/data traffic
sudo -n tar --use-compress-program="pigz -p 2 -1" -cf "$BK/data-tasks.tar.gz"   -C /opt/artex/data tasks
```

**校验**（`tar -tzf` 逐个列条目，确认真能读）：

```bash
for f in "$BK"/*.tar.gz; do echo "$(basename $f): $(sudo -n tar -tzf "$f" | wc -l) entries"; done
sudo -n zcat "$BK/artex.sql.gz" | grep -c 'CREATE TABLE'
```

## 2. 停服务 → 换二进制 → 启服务

### ⚠️ 任务运行期间部署 = 掐断在跑的意图

`systemctl stop artex` 会取消所有在跑的 worker run，它们被落成
`blocked: context canceled`，**内容全部丢掉**（已写回的事实还在，但那一步
的探测没了）。实测 2026-10-21 连续部署两版，任务 4 的 8 个意图全被掐断。

**部署前先看有没有任务在跑**：

```bash
sudo -n -u postgres psql -d artex -tA -F'|' -c \
  "SELECT id, status, left(name,30) FROM tasks WHERE status NOT IN ('done','failed','timeout');"
```

有在跑的任务时，两个选择：

- **等它跑完**（推荐，改动不急时）
- **先优雅暂停**（让 worker 写回成果再停）：
  ```bash
  curl -s -X POST "$API/api/tasks/<id>/control" -H "Authorization: Bearer $TOKEN" \
       -H 'Content-Type: application/json' -d '{"paused":true}'
  ```
  等它进 paused 再 stop。

**万一已经掐断了**，用官方接口把 blocked 意图恢复成 open（worker 会重新领取）：

```bash
curl -s -X POST "$API/api/tasks/<id>/intents/rerun-blocked" \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{}'
# → {"id":"4","queued":false,"reopened":8}
```

### 实际替换步骤

```bash
sudo -n systemctl stop artex

SRC=/tmp/artx-upload/unpack/artex-<版本>-linux-amd64
D=/opt/artex

# 二进制：先写 .new 再 mv -f，避免 ETXTBSY（正在运行的二进制写不进去）
sudo -n cp "$SRC/artex" "$D/.artex.new"
sudo -n chmod +x "$D/.artex.new"
sudo -n mv -f "$D/.artex.new" "$D/artex"

sudo -n cp "$SRC/artex-hostd" /usr/local/bin/.artex-hostd.new
sudo -n chmod +x /usr/local/bin/.artex-hostd.new
sudo -n mv -f /usr/local/bin/.artex-hostd.new /usr/local/bin/artex-hostd

# ★ skills 必须用「合并」写法：cp -r "$SRC"/skills/. "$D"/skills/
#   写成 cp -r "$SRC"/skills "$D"/ 时，目标 skills 已存在，GNU cp 的行为
#   不保证把每个子 skill 补齐——实测漏掉过 api-recon，而 DB 里三个 agent
#   都绑定了它，结果 worker/auto/pentest 静默拿不到这个能力。
sudo -n mkdir -p "$D/skills"
sudo -n cp -r "$SRC"/skills/. "$D"/skills/

sudo -n cp "$SRC/start.sh" "$D/start.sh"
sudo -n chmod +x "$D/start.sh"
echo "<版本>" | sudo -n tee "$D/.version" >/dev/null
sudo -n chown -R artex:artex "$D"

sudo -n systemctl start artex
sleep 7
sudo -n journalctl -u artex --since '30 seconds ago' --no-pager | grep -Ei 'listening|panic'
```

**部署后必查**：

```bash
sudo -n ls /opt/artex/skills/          # skill 数量应与 release 里一致
sudo -n cat /opt/artex/.version
```

## 3. 已知的环境事实

- **服务进程带着 `HTTP_PROXY` / `HTTPS_PROXY`**（systemd `Environment=`）。
  Go 里 `http.DefaultTransport.Clone()` 会继承这个代理——想「直连」必须
  **显式 `transport.Proxy = nil`**。本项目已有三处按这个约定写：
  `agent/provider.go`（LLM）、`traffic/traffic.go`（目标流量）、
  `server/proxypool_api.go`。
- **出网代理 `10.10.70.14:7897` 对部分站点不通**（实测 cisa.gov /
  services.nvd.nist.gov 会「CONNECT 200 后 TLS 握手 EOF」，而 github 正常）。
  直连这两个源是通的。
- 测试机到 GitHub 间歇性失败；本机 GitHub 需走 Clash 代理
  （`socks5h://127.0.0.1:7897`）。

## 4. 登录凭据

- 用户名固定 `ARTEX`；密码是 bcrypt hash，存在 `settings` 的
  `auth.password_hash`。
- **重置密码**：删掉那一行 → `POST /api/auth/init`（body `{"password":"..."}`）
  → 返回 token。`init` 用 `InsertSettingIfAbsent` 保证只能设一次。
- 改密码用 `POST /api/auth/change-password`（需要**旧密码** + 有效 token）。

## 5. 全量重置（想从零开始时）

备份之后：

```bash
sudo -n systemctl stop artex
sudo -n -u postgres psql -d artex -v ON_ERROR_STOP=1 <<'SQL'
BEGIN;
-- ★ 逐表 DELETE，**不要用 TRUNCATE ... CASCADE**
--   CASCADE 沿着外键反向清掉「保留表」：实测 task_scope 引用 companies，
--   CASCADE 把 companies/company_scope 清了；agent_triggers 也一起没了
--   ——reporter 的 report_finding 触发器丢失后，漏洞上报不再自动触发
--   报告 Agent，流量证据也就没人去核对了。
--   顺序：先删被引用的，再删引用方。
DELETE FROM finding_traffic_bindings;
DELETE FROM traffic_evidence_snapshots;
DELETE FROM finding_retests;
DELETE FROM findings;
DELETE FROM activity;
DELETE FROM server_logs;
DELETE FROM llm_records;
DELETE FROM llm_usage;
DELETE FROM tool_usage;
DELETE FROM skill_usage;
DELETE FROM conversation_activities;
DELETE FROM side_question_requests;
DELETE FROM side_question_sessions;
DELETE FROM conversations;
DELETE FROM main_sessions;
DELETE FROM notification_events;
DELETE FROM notification_deliveries;
DELETE FROM intercept_pending;
DELETE FROM task_archives;
DELETE FROM scheduler_state;
DELETE FROM task_relations;
DELETE FROM task_asset_links;
DELETE FROM task_scope;
DELETE FROM task_constraints;
DELETE FROM task_intercept_rules;
DELETE FROM task_llm_profiles;
DELETE FROM exploration_anchors;
DELETE FROM exploration_edges;
DELETE FROM exploration_nodes;
DELETE FROM explorations;
DELETE FROM tasks;
DELETE FROM assets;
DELETE FROM settings WHERE key = 'auth.password_hash';
COMMIT;
SQL

for d in tasks sessions transcripts traffic evidence; do
  sudo -n rm -rf "/opt/artex/data/$d"/* 2>/dev/null || true
  sudo -n mkdir -p "/opt/artex/data/$d"
  sudo -n chown artex:artex "/opt/artex/data/$d"
done
sudo -n systemctl start artex
```

**重置后必查保留表**（CASCADE 事故的发现手段）：

```bash
sudo -n -u postgres psql -d artex -tA -c "
SELECT 'companies',count(*) FROM companies
UNION ALL SELECT 'company_scope',count(*) FROM company_scope
UNION ALL SELECT 'agent_triggers',count(*) FROM agent_triggers
UNION ALL SELECT 'agents',count(*) FROM agents
UNION ALL SELECT 'tools',count(*) FROM tools
UNION ALL SELECT 'settings',count(*) FROM settings"
```

`agent_triggers` 必须是 **≥1**（reporter 的 report_finding 触发器）。
`companies` / `company_scope` 若之前有值，重置后要恢复（备份里可取）。

**保留**（删了系统就没法用）：`agents` / `agent_prompts` / `agent_triggers` /
`agent_visibility` / `agent_skill_visibility` / `agent_prompt_vars` / `tools` /
`settings` / `llm_profiles` / `llm_profile_health` / `intercept_rules` /
`asset_intercept_rules` / `mcp_servers` / `notification_channels` /
`task_templates` / `task_categories` / `companies` / `company_scope` /
`vuln_*`。

`nuclei-templates`（934M）保留——重下很慢。

## 6. 部署后的自检清单

```bash
TOK=$(curl -s -X POST http://127.0.0.1:8787/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ARTEX","password":"<密码>"}' | python3 -c "import json,sys;print(json.load(sys.stdin)['token'])")

curl -s http://127.0.0.1:8787/api/health
curl -s http://127.0.0.1:8787/api/settings -H "Authorization: Bearer $TOK" | head -c 200
```

- `agent_traffic_binding` 应为 `true`（流量证据自动绑定）。
- `compaction_max_tokens` / `compaction_max_members` 显示 0 是**正常**的
  ——0 表示「用代码默认值」（65536 tokens / 6 成员），不是没配。
- 浏览器打开 `/function/tasks` 应看到「暂无任务」。
